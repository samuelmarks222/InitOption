# Independent Canvas financial chart

## Run

```sh
npm ci
npm run chart:bundle
npm run chart:simulation
```

Open port **8090**, then click **Connect**. The server serves the standalone
`chart.html`, `/ticks` WebSocket and `/history` tick API on the same origin, so
HTTPS preview proxies work without browser localhost URLs. It binds to 0.0.0.0.
The banner and server log explicitly identify **SIMULATION — NOT REAL MARKET DATA**.
No prices are generated by the frontend. Simulation is deliberately separate from
the dashboard's live/trading adapter, which rejects `source: "simulated"`.

`financial-chart/chart.html` is the complete, self-contained deliverable: HTML,
CSS and bundled original JavaScript, with no external frontend dependency, CDN,
or financial renderer. It can also be opened as a file; enter absolute gateway
URLs in that case. Rebuild it after changing source modules or the native renderer.

## Modules

- `ticks.js`: validation, bounded ordered tick buffer, duplicate rejection,
  independent epoch-aligned OHLC aggregation, recursive HA, Area interval lock,
  and synchronous incremental `TickProcessor` subscriptions.
- `adapter.js`: native browser WebSocket, backoff reconnect, disconnect cleanup,
  history/live synchronization, symbol/source isolation, retained replay identities.
- `frontend.js`: standalone integration, per-tick OHLC/HA and SMA updates,
  type/timeframe controls and time/price anchored trendlines.
- `../src/components/trading/engine/native/chart.ts`: shared Canvas renderer,
  high-DPI backing store, resize observer, axis/grid/crosshair/current-price line,
  panning, wheel/pinch zoom, coordinate mapping and fit-to-visible scaling.
  Binary searches limit paint/scale work to the visible history window. RAF
  coalesces paint requests only; it does not change prices or candle duration.
- `../server/market-data/simulation.js`: configurable arithmetic Brownian process
  with variable drift, trend/consolidation regimes and soft boundary forces.
- `../server/market-data/server.js`: HTTP/history plus WebSocket streaming every
  100 ms, bounded history, subscriptions, heartbeat and slow-consumer protection.

All fifteen required intervals are supported. Empty intervals remain absent in the
standalone tick reconstruction; no invented trades or missed OHLC are backfilled.
Japanese candles/bars use actual OHLC; Area uses close; HA is explicitly derived.
Displayed price formatting never rounds the stored incoming value.

## Live gateway contract / deployment prerequisite

Choose **Live market**, enter an actual WebSocket URL, optional HTTP history URL,
and the exact symbol, then Connect. Live mode never falls back to simulation.

WebSocket subscribe/unsubscribe messages:

```json
{"type":"subscribe","channel":"ticks","symbol":"EUR/USD"}
```

Incoming single ticks, or `{"ticks": [...]}` batches:

```json
{"type":"tick","symbol":"EUR/USD","timestamp":1763923200.245,"price":1.08452137,"sequence":94832014,"volume":2}
```

Timestamps are original Unix **seconds**; sequence and volume are optional.
Stable sequence identifiers are strongly recommended. Without them, identity
uses timestamp/price/volume and cannot distinguish two otherwise identical trades.
Sequence IDs must not reset on reconnect without a new stream session. Source
isolation is explicit: live mode rejects simulation-tagged ticks; simulation mode
requires `source: "simulated"`. Live providers are still trusted to label honestly.
Late historical ticks correct reconstructed bars without rewinding latest price.
Future ticks beyond 30 seconds of client time are rejected; synchronize host clocks.

The history endpoint accepts `?symbol=...&from=<seconds>` and returns
`{"ticks": [...]}` using the same tick contract. It must allow the frontend origin
and use HTTPS when the chart is served over HTTPS. A 15-second timeout prevents
history from blocking streaming forever. During loading, incoming ticks are buffered,
then history and live data are deduplicated and sorted before the snapshot is
published. Reconnect requests overlap the latest retained timestamp. Providers
must return complete history for the requested range; this client cannot infer
missing ticks, pagination or an undocumented vendor schema. History failures show
`history-unavailable`, not fabricated candles. Browser native WebSockets cannot
set arbitrary Authorization headers: use an authenticated same-origin gateway
or the provider's supported secure authentication protocol, never embed secrets.

**No verified production market history endpoint or OTC routing contract was found
in this repository. This adds a configurable adapter, not a claim that such a
provider is connected.** The dashboard continues to require
`VITE_MARKET_DATA_WS_URL` and does not yet consume this new standalone history API.
Its screenshot's empty chart cannot honestly be fixed with actual live prices
until a real gateway is configured. Other existing app surfaces (e.g. asset quotes,
pair information and signals) still have deterministic data paths; those are not
certified live by this change.

## Simulation configuration

Environment variables: `PORT` (8090), `SIM_SYMBOL` (DEMO/USD), `SIM_PRICE` (100),
`SIM_DRIFT` (.02 price units/second), `SIM_VOLATILITY` (.2 units/sqrt(second)),
`SIM_PRECISION` (5), `SIM_SUPPORT` (90), `SIM_RESISTANCE` (110), and
`SIM_BOUNDARY_STRENGTH` (.3). Support/resistance are soft drift forces, not clamps
or guaranteed bounds. Prices stay positive; server-side tick output alone is
quantized to configured precision. Client OHLC is never eased/interpolated.

This sample simulation service has no user authentication or trading endpoints.
Do not expose it as a production exchange gateway or use it to settle real trades.
Deploy behind appropriate TLS, access controls, rate limiting and monitoring.
Retention defaults to 200,000 ticks (~5.5 hours at 10 Hz); longer 4h lookbacks
require larger configurable buffers and/or actual history. Four-hour alignment
is tested using explicit timestamps, without waiting four wall-clock hours.

## Dashboard integration and preservation

The dashboard already uses the original native Canvas renderer, not third-party
financial runtime code. Its existing type-only compatibility contracts remain for
indicators/drawing overlays. This patch leaves trading controls/layout alone,
shares actual source/symbol connections across timeframe subscribers, keeps the
last connection briefly alive across view changes, and disposes it after the last
subscriber leaves. The dashboard keeps its existing Area lock/restore and overlay
coordinate contracts. The standalone is a companion interface, not a replacement
dashboard or a new real-money execution system.

## Validation and remaining acceptance work

```sh
npm run chart:test       # Node engine/adapter/server tests
npm run chart:bundle     # verifies self-contained frontend bundles
npm run build            # existing dashboard production build
```

Coverage includes exact rapid reversals, 20,000 ticks vs full reconstruction,
5s/4h boundaries, every timeframe, deduplication and late history, Area lock,
HA recursion, real WebSocket simulation/history, reconnect/cancel and no synthetic
live fallback. Existing Canvas tests cover all rendering families, coalesced paints,
DPR 2 and mobile-size resizing, retained viewport and overlay-coordinate mapping.

Automated Canvas checks use mocked drawing contexts, not visual browser approval.
Authenticated desktop/mobile dashboard, actual gateway outage recovery, multi-touch,
drawing/indicator settings persistence, and production-load soak testing still
need manual/device acceptance. No guarantee of flicker-free operation on every
device or completed production sign-off is implied. Repository-wide existing
TypeScript errors and three legacy simulation-test failures remain separate work.
